# 0x01

OpenMint 最初的设想是做一个能自动运行的任务看板：

> 你把任务丢上去，它就能自动完成。

import demo from './images/demo.webp';

<BaseImage src={demo.src} alt="任务看板" />

每个任务由 3 个角色负责：
1. Worker 负责干活
2. Boss 负责拆解任务和验收
3. Delegate 负责代理你自动做决策

依次经过三重标准层层打磨：
1. **make it work**：能运行，复现问题并定位到根本原因，彻底修复而不是打补丁
2. **make it professional**：够专业，达到生产环境可用水准，健壮稳定高性能，采用主流、现代化的技术栈与设计模式
3. **make it art**：艺术品，大道至简，不多不少，追求极致的用户和开发者体验，如艺术品一般，有品味，有温度，有灵魂

整个过程无人值守，循环（Loop）自动运行，直至任务达标完成。

最终目的只有一个：

尽量少得让人参与其中，把注意力解放出来，享受美好生活。

你只需负责提出问题或想法，Agent Loop 自动帮你完成任务，层层打磨，臻于完美。

**You shape it, we mint it.**

# 0x02

在 OpenMint 里，有一个有趣的设定：

Boss 从不把详细答案告诉给 Worker，而是像老师一样启发式教学：

Boss 从不会说“你应该 xxx“，而是说“试试看 xxx“，

用问题引导执行者自行找到答案、获得成长。

**授人以鱼不如授人以渔** —— 引导，而非直接给出答案。

这样做的另一个好处是，当 Worker 陷入原地循环或者方向错误时，

Boss 可以及时予以指导，或者直接重置上下文启用新的会话重新开始。

如果任务确实无解，则裁定为 **impossible** 挂起，避免无休止的无效迭代。
